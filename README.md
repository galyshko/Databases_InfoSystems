1. **Транзакції у Redis**

Ознайомтесь з командами MULTI, EXEC, DISCARD, WATCH.

![alt text](img/image.png)

WATCH balance – спостерігає за ключем balance.

MULTI – починає транзакцію.

DECR balance – зменшує balance на 1.

INCR purchases – збільшує purchases на 1.

EXEC – виконує зміни, якщо ключ balance не був змінений.

![alt text](img/image1.png)

MULTI – починає транзакцію.

SET user:1:name "John" – створює ключ user:1:name зі значенням "John".

SET user:1:age 30 – створює ключ user:1:age зі значенням 30.

SET user:1:city "New York" – створює ключ user:1:city зі значенням "New York".

EXEC – виконує всі команди транзакції.

![alt text](img/image2.png)

WATCH balance – Redis спостерігає за ключем balance. Якщо значення цього ключа змінюється до виконання транзакції, вона не буде виконана.

MULTI – починається транзакція.

DECR balance – зменшує значення ключа balance на 1.

INCR purchases – збільшує значення ключа purchases на 1.

EXEC – виконуються всі команди транзакції. Якщо між WATCH і EXEC значення balance змінюється, транзакція скасовується.

6. **Теоретичне завдання**

**Визначте, які з нових механізмів Redis можуть бути корисними у великих розподілених системах.**

Streams – обробка подій і черги повідомлень.

Cluster – автоматичне шардінг і масштабування.

Sentinel – висока доступність і автофейловер.

Modules – розширення Redis (пошук, JSON, графи).

ACL – контроль доступу для безпеки.

Active-Active (CRDT) – реплікація між датацентрами без конфліктів.

**Які плюси і мінуси Redis як брокера повідомлень?**

**Плюси** Redis як брокера повідомлень:
Швидкість: Висока продуктивність завдяки зберіганню в пам'яті.

Простота налаштування: Легко інтегрується та налаштовується.

Pub/Sub: Підтримка реального часу та миттєвого обміну повідомленнями.

Відмовостійкість: З Redis Sentinel для високої доступності.

Масштабованість: Через Redis Cluster.

**Мінуси:**
Не гарантована доставка: Повідомлення можуть губитися при відсутності підписника.

Відсутність довговічності: Повідомлення не зберігаються після обробки.

Обмежені черги: Немає гарантованої доставки або повторних спроб.

Масштабування на великі системи: Для дуже великих навантажень краще використовувати Kafka чи RabbitMQ.
